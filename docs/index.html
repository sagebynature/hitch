Why Hitch?

Agent lifecycle control should be portable.

Every harness has its own event names, payloads, response rules, and lifecycle boundaries. Hitch gives developers and teams one stable contract instead of forcing every guardrail, logger, and workflow hook to chase native formats.

Normalize once

Source hook JSON becomes a Hitch event envelope with harness identity, source event type, normalized event type, and preserved native payload.

tool.requestedsession.started

Route anywhere

Handlers are ordinary executables, and events arrive through a local-first REST API that also works for remote service deployments.

shellpythonnodego

Control centrally

Handler routing, synchronous decisions, audit records, and replay live behind one server config instead of five harness-specific integrations.

The contract

One control plane for local and remote agent events.

Hitch stays boring on purpose: native JSON in, normalized events over REST, external commands out, audit records underneath, and harness-native responses at the edge.

01Harness

Codex, Hermes, Pi, OMP, or OpenCode emits native lifecycle data.

02REST API

The hook shim posts async or sync events to a local or remote Hitch server.

03Envelope

Hitch maps the event into a stable schema while retaining the original payload.

04Routing

Server config sends matching events to policy, audit, context, or workflow handlers.

05Control

Decisions become native harness responses, audit records, and replayable history.

For solo developers

Ship one guardrail, observer, context injector, or workflow hook without binding it to one agent CLI.

For teams

Let developers choose their harness while platform teams centralize lifecycle routing, execution, audit, and replay.

Quick start

Local-first. Remote-ready.

Run Hitch as a local daemon for your own agents, or point hook shims at a shared Hitch service for team-wide lifecycle routing. The same handler protocol works in both modes.

The source installer seeds Hitch config with hitch config init and adds missing managed default sections to existing valid config. hitch-client install installs managed hooks and extensions for supported harnesses.

curl -fsSL https://raw.githubusercontent.com/sagebynature/hitch/main/scripts/install.sh | sh
hitch serve --config ~/.config/hitch/config.toml
hitch status --json
hitch doctor --json
hitch-client install --only codex --dry-run --json
hitch-client install --only opencode --yes --json
