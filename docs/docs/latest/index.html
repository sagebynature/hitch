Hitch Documentation

Hitch is a local universal hook adapter for Codex, Pi, OMP, and Hermes. It gives open-source developers one portable handler protocol for guardrails, audit logs, policy checks, context injection, and result transformation.

Quickstart

Install from latest source, start the local server, check health, then preview and install supported hooks.

curl -fsSL https://raw.githubusercontent.com/sagebynature/hitch/main/install.sh | sh
hitch serve --config ~/.config/hitch/config.toml
hitch status --json
hitch doctor --json
hitch install --only codex --dry-run --json
hitch install --only codex --yes --json

The default server listens on 127.0.0.1:8799 and stores SQLite audit records at ~/.local/share/hitch/events.sqlite.

Installation

The source installer checks for git and go, builds ./cmd/hitch, installs the binary into $HITCH_INSTALL_DIR or ~/.local/bin, verifies hitch --version, and offers hook setup when stdin is interactive.

Build locally

make build
./bin/hitch --version
./bin/hitch serve --config config/default.config.toml

Hook install commands

hitch install --dry-run --json
hitch install --all --dry-run --json
hitch install --only codex --yes --json
hitch uninstall --only codex --yes --json

The current installer seeds ~/.config/hitch/config.toml when missing and installs Hitch-managed Codex hooks into ~/.codex/hooks.json. Hermes, Pi, and OMP are detected and reported, but real hook patching is not implemented for them yet.

Configuration

Hitch reads user configuration from ~/.config/hitch/config.toml. Development commands default to config/default.config.toml unless a command receives --config or -config.

SectionPurpose
[server]Local API bind address and request size limit.
[log]Operational logging. Native payloads are not included by default.
[audit]Event journal persistence. SQLite is the verified backend.
[handlers.<name>]External command handlers, event filters, mode, timeout, and error policy.
[harness.<name>]Per-harness enable flags.

Strict validation rejects unknown config keys and invalid server ports, request sizes, log values, audit backends, handler event names, handler modes, and handler error or timeout policies.

[handlers.noop_observer]
command = ["hitch", "handler", "noop-observer"]
events = ["*"]
mode = "sync"
timeout_ms = 1000
on_error = "fail_open"
on_timeout = "fail_open"

Handler protocol

A handler is any executable command configured in Hitch. Hitch writes one normalized event envelope JSON object to handler stdin. The handler may write one JSON result object to stdout.

{
  "status": "ok",
  "decision": {
    "behavior": "none"
  }
}
  • Allowed statuses: ok, error, timeout.
  • Allowed decisions: none, allow, deny, block, continue, stop, transform, replace_result, inject_context, handled.
  • If decision is omitted, Hitch treats it as {"behavior":"none"}.
  • Hitch sets HITCH_CHILD=1 on child handler processes for recursion guards.

Verified behavior includes stdout JSON parsing, invalid stdout persistence as error, timeout persistence as timeout, separate stderr capture, decision precedence by configured handler order, ordered context injection concatenation, and rejection of multiple transforms unless transform chaining is explicitly configured.

Local HTTP API

Hitch exposes a local API for health checks, event ingestion, synchronous dispatch, event inspection, and replay-driven workflows.

EndpointUse
GET /v1/healthReturn server health status.
POST /v1/eventsIngest async observer events.
POST /v1/dispatch-syncRun sync handlers and return a harness-native response.
GET /v1/events/<id>Inspect stored inbound, normalized, handler, and native response records.
 
curl -sS -X POST http://127.0.0.1:8799/v1/dispatch-sync \
  -H 'content-type: application/json' \
  -d '{
    "harness": "codex",
    "native_event_type": "PreToolUse",
    "native_payload": {
      "hook_event_name": "PreToolUse",
      "tool_name": "Bash",
      "tool_input": {"command": "pwd"}
    }
  }'

Harness contracts

Hitch supports two dispatch modes: async observer events use POST /v1/events, and sync control events use POST /v1/dispatch-sync and return a native response.

HarnessCurrent contract
CodexMaps native command hook payloads and translates decisions to Codex stdout JSON. The verified path covers every supported Codex lifecycle event and PreToolUse deny translation.
HermesMaps shell hook payloads and translates decisions to Hermes stdout JSON. The verified pre_tool_call block response is {"action":"block","message":"..."}.
Pi / OMPMaps extension callback events in Go and shares a TypeScript adapter-response contract for callback return values or in-place event mutation.

Async adapter calls print nothing and ignore Hitch network failure. Sync adapter calls emit a harness-native no-op response when Hitch is unreachable or returns no native response.

Replay and inspect

Use inspect-event to inspect the persisted audit view for a normalized event. Use replay to re-run configured sync handlers against stored normalized events.

hitch inspect-event --config config/default.config.toml norm_...
hitch replay --config config/default.config.toml --dry-run norm_...
hitch replay --config config/default.config.toml norm_...

Dry-run replay returns the stored event envelope without writing records. Replay without --dry-run persists new handler invocation records linked by replay_source_id to the source normalized event id.
